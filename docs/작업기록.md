## 4. 설계 결정

### 4-1. 손으로 옮기지 않고 "생성"한다

25쪽 · 블록 408개를 손으로 옮기면 반드시 빠지거나 틀린다.
**원본 데이터를 Node 로 읽어 HTML 을 찍어내는 생성기**를 만들었다.

```
_원본/src/data/*.js·json
      ↓ _build/gen/load.mjs      (Vite 전용 문법만 걷어내고 그대로 import)
      ↓ _build/gen/blocks.mjs    (블록 14종 → HTML)
      ↓ _build/gen/pages-*.mjs   (페이지별 조립)
      ↓ _build/build.mjs
   *.html 25쪽 (인라인 완성본)
```

원본 데이터가 바뀌면 `node _build/build.mjs` 한 줄로 25쪽이 다시 만들어진다.

### 4-2. Vite 전용 문법 두 가지만 걷어냈다

원본 데이터 모듈은 Node 에서 그냥 import 되지 않았다.

```
Cannot read properties of undefined (reading 'BASE_URL')   ← import.meta.env
Module "…/content.json" needs an import attribute          ← JSON import
```

원본 파일은 건드리지 않고 **임시 복사본에서만** 두 곳을 바꿔 읽는다
(`_build/gen/load.mjs`). 원본을 고치면 나중에 원본과 대조할 수 없게 된다.

### 4-3. Supabase 를 걷어냈다

원본은 구글·카카오 OAuth 로그인과 진도 동기화에 Supabase 를 쓴다.
**폐쇄망 강의실에서는 로그인 자체가 불가능하다.**

진도는 `localStorage` 한 곳에만 남긴다. 키 접두사는 원본과 같은
`nonghyupsaryo_` 를 유지했다. 값이 깨져 있으면 빈 것으로 시작한다.

### 4-4. 외부 요청을 전부 없앴다

"보안 이슈로 로컬에서 작업한다"는 조건을 그대로 받아들였다.

| 원본 | 이 정적본 |
|---|---|
| Tailwind 빌드 | 손으로 쓴 CSS (토큰은 `tailwind.config.js` 에서 그대로 옮김) |
| Font Awesome | 인라인 SVG · 이모지 |
| 웹폰트 CDN | 안 검 — 설치돼 있으면 쓰고 없으면 OS 기본 글꼴 |
| favicon 파일 | `data:` URI SVG |
| Supabase | 없음 |

검증에서 **25쪽 모두 외부 요청 0건**을 확인했다.
남은 외부 링크는 자료 내려받기(GitHub raw) 1곳과 도구 공식 사이트뿐이고,
둘 다 사용자가 눌렀을 때만 나간다.

### 4-5. 색과 글꼴은 원본 그대로

`tailwind.config.js` 의 NH 아이덴티티를 CSS 변수로 옮겼다.

```
딥 그린 #12522e (헤더·표머리)   NH 그린 #1fa054 (강조)
골드   #fec20d (농협 심볼 공식 CI · 포인트)
```

### 4-6. 사이드바는 화면마다 모드가 다르다

원본 `Sidebar.jsx` 가 경로에 따라 6가지 목차를 보여 준다. 그대로 옮겼다 —
교재(현재 차시의 절 목록까지 펼침) · 도구 · 소개 · 일정 · 실습 · 부록.

## 7. 도중에 잡힌 문제

### 7-1. 좁은 화면에서 35px 이 잘려 나갔다

```
✗ part-2  360px  overflow=7
✗ part-8  360px  overflow=35
```

`body{overflow-x:hidden}` 덕분에 **실제로 밀리지는 않았지만**(스크롤 테스트로
확인) 그만큼 글자가 잘려 읽을 수 없었다.

원인을 찾는 데 두 번 헛짚었다.

1. **첫 진단이 틀렸다.** 표 셀들이 범인처럼 나왔는데, 그 셀들은
   `overflow-x:auto` 컨테이너 안에 있어 이미 잘 잘려 있었다.
   `getBoundingClientRect()` 는 **잘린 요소도 원래 좌표를 보고한다.**
2. 스크롤 컨테이너 안쪽을 제외하니 **넘치는 요소가 하나도 없다**고 나왔다.

결국 요소를 하나씩 `display:none` 으로 숨겨 가며 `scrollWidth` 가 줄어드는
지점을 찾았다.

```
d6 LI  −35px | ② 사용할 도구: … (ChatGPT·Claude·Gemini·Perplexity…)
```

**원인:** 한글 가독성을 위해 건 `word-break:keep-all` 이,
가운뎃점으로만 이어진 `ChatGPT·Claude·Gemini·Perplexity` 를 **한 낱말**로
보고 끊지 않았다.

**수정:** `keep-all` 은 유지하되 넘칠 때만 끊게 했다.

```css
body{ word-break:keep-all; overflow-wrap:break-word; }
.b-para,.b-bullets li,.b-obj li,.b-note,.cell-pre,…{ overflow-wrap:anywhere; }
```

고친 뒤 75개 조합 전부 통과.

> 한글 사이트에서 `keep-all` 만 걸고 끝내면 이 사고가 난다.
> 영문 도구 이름을 나열하는 교육 자료라면 특히 그렇다.

### 7-2. 진단 도구를 먼저 의심할 것

7-1 의 1·2번은 **화면이 아니라 진단이 틀린** 경우였다.
증상만 보고 멀쩡한 표 스타일을 건드렸다면 엉뚱한 곳을 고칠 뻔했다.

## 8. 프롬프트 자동 채점 이식 (추가 요청)

정적 변환 1차에서 뺐던 기능을 요청에 따라 넣었다.
원본 `promptLab.js` 의 `evaluatePrompt()` 를 React 없이 브라우저에서 그대로
돌도록 옮긴 것이다(`_build/gen/scoring.mjs`).

### 무엇을 하는가

업무 상황 6가지 중 하나를 고르고 프롬프트를 쓰면, 5요소를 **각 20점씩 100점
만점**으로 즉시 채점한다. 등급(S~D), 요소별 막대, 부족한 부분에 대한 피드백이
글자를 칠 때마다 갱신된다. 채점은 브라우저 안에서만 이뤄지고 어디로도 보내지 않는다.

시나리오마다 채점에 쓰는 낱말 목록(`keywords` · `roleKeywords` ·
`constraintKeywords` · `formatKeywords`)이 다르므로, 같은 프롬프트라도 상황을
바꾸면 점수가 달라진다. 원본이 그렇게 설계돼 있고 그대로 따랐다.

### 원본과 같은 점수가 나오는지 확인했다

눈으로 "돌아간다"만 보고 넘기면, 가점 조건 하나를 잘못 옮겨도 모른다.
**원본 함수를 Node 에서 직접 불러 정답으로 놓고 화면 결과와 대조**했다.

```
시나리오 3종 × 입력 4종 = 12건
✓ 시나리오1 · 짧은 프롬프트     화면  13점 D   원본  13점 D   피드백 6/6
✓ 시나리오1 · 다듬은 프롬프트    화면  96점 S   원본  96점 S   피드백 1/1
✓ 시나리오2 · 다듬은 프롬프트    화면  87점 A   원본  87점 A   피드백 2/2
✓ 시나리오3 · 다듬은 프롬프트    화면  84점 A   원본  84점 A   피드백 1/1
…
원본과 점수 완전 일치
```

총점 · 등급 · 피드백 개수까지 12건 모두 일치했다.
360px 에서 가로 넘침 0, 입력 글자 16px(iOS 확대 방지)도 함께 확인했다.

### 옮기면서 손댄 곳

원본은 `new RegExp(actionRe, 'g')` 로 정규식에 플래그를 다시 붙인다.
이식본에서는 같은 패턴을 `g` 플래그를 단 리터럴로 직접 썼다 — 동작은 같고
읽기가 쉽다. 그 외 점수 배분 · 가점 조건 · 피드백 문구 · 등급 구간은
한 글자도 바꾸지 않았다.

시나리오 데이터는 `<script>` 안에 JSON 으로 심는다. `</script>` 가 문자열에
섞여 스크립트가 조기 종료되지 않도록 `<` 를 이스케이프한다.

## 9. 남은 것 / 하지 않은 것

- **회사 소개(`company.html`)는 원본 그대로 둔다.** 확인을 거친 결정이다 (5장).

  `prefers-reduced-motion`. 스크린리더 실제 테스트는 하지 않았다.
